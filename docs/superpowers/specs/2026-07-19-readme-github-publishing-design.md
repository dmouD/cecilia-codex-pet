# 塞西莉亚 Codex 宠物 README 与 GitHub 发布设计

## 目标

将项目作为公开仓库 `dmouD/cecilia-codex-pet` 发布，并把根目录 `README.md` 扩展为兼顾普通用户与开发者的单页渐进式教程。README 必须让没有前端经验的用户能够启动和操作宠物，也必须让开发者无需阅读源码即可正确调用公开接口。

本次只改进文档和发布配置，不改变宠物的视觉、状态机或交互行为。

## 方案选择

采用“单 README 渐进式教程”：先给出项目效果和最短启动路径，再逐步展开交互、状态、API、集成、素材扩展与故障排查。

未采用以下方案：

- README 与独立 API 文档拆分：会让核心教程分散，不符合用户要求。
- 从代码注释自动生成 API 文档：当前公开 API 很小，引入生成依赖得不偿失。

## 目标读者

- 普通用户：希望在本地打开、操作和体验塞西莉亚宠物。
- 开发者：希望从 Codex 状态桥或其他 JavaScript 环境驱动宠物状态。
- 二次创作者：希望在保持接口不变的情况下替换图像素材或增加内部状态。

README 以简体中文为主，保留代码标识符和必要的英文状态名。

## README 信息结构

1. 标题、项目简介和主视觉预览。
2. 功能概览：离线、自包含、响应式、可拖动、键盘可访问、状态 API。
3. 快速开始：环境要求、获取代码、启动本地服务器、打开地址。
4. 跨平台运行：Windows、macOS 和 Linux 命令。
5. 操作教程：单击、三击、拖动、状态按钮、演示按钮、Enter/Space。
6. 状态参考：六种持久状态与 `clicked` 临时状态。
7. 公开 API：对象位置、方法、属性、参数、返回值、副作用和错误处理。
8. Codex/外部状态集成：状态映射、最小桥接函数和安全调用方式。
9. 素材与定制：运行时素材目录、文件名约定、回退规则和源码素材目录。
10. 行为规则：自动演示、眨眼、休眠和粉色伙伴出现条件。
11. 测试、项目结构、常见问题、隐私和版权说明。

## 公开接口契约

页面加载完成后通过 `window.ceciliaPet` 暴露只读对象：

### `setState(state)`

- 接受 `idle`、`thinking`、`coding`、`success`、`error`、`sleeping`。
- 调用时停止自动演示，并切换到指定持久状态。
- 成功返回 `true`；未知状态返回 `false`，并在控制台对同一未知值最多警告一次。
- `clicked` 是内部临时状态，不能通过该方法设置。

### `startDemo()`

- 启动或保持自动状态轮播。
- 无参数，无返回值约定。
- 更新页面演示按钮的文本和 `aria-pressed`。

### `stopDemo()`

- 停止自动状态轮播并保留当前状态。
- 无参数，无返回值约定。
- 更新页面演示按钮的文本和 `aria-pressed`。

### `state`

- 只读 getter，返回当前可见状态字符串。
- 短暂点击反馈期间可能返回 `clicked`，结束后恢复先前持久状态。

README 不把内部类、计时器或 DOM 节点描述为稳定公开 API。

## 教程与集成示例

README 提供：

- 使用页面按钮和 `window.ceciliaPet` 控制状态的最小示例。
- 将常见任务阶段映射为宠物状态的示例，例如等待→`idle`、分析→`thinking`、执行→`coding`、成功→`success`、失败→`error`。
- 在调用前检查全局对象是否存在的防御式写法。
- 说明独立页面不会读取 Codex 私有任务、账号、剪贴板或聊天内容；任务状态必须由外部桥显式传入。

## 素材与版权

- `assets/pet/` 是浏览器直接加载的运行时素材。
- `assets/source/` 保存可复现去背流程的键控源图。
- `assets/references/` 保存创作参考，不作为页面运行依赖。
- 缺失或加载失败的状态图回退到 `cecilia-idle.png`。
- README 明确代码与角色素材可能适用不同权利；公开仓库不自动附加开源许可证，也不宣称拥有原作角色或参考图权利。

## 验证标准

- README 中的所有命令能够从仓库根目录运行。
- API 名称、状态值、返回值和副作用与源码一致。
- Markdown 不含占位符、损坏链接或本机绝对路径。
- `npm test` 全部通过，所有 `src/*.js` 通过语法检查。
- `git diff --check` 无格式错误，工作树在提交后保持干净。

## GitHub 发布方式

1. 创建公开仓库 `dmouD/cecilia-codex-pet`，不自动生成 README、许可证或 `.gitignore`。
2. 添加 `origin` 远程地址。
3. 先推送本地 `master` 作为远程默认基线，再推送 `feature/cecilia-codex-pet`。
4. 创建从 `feature/cecilia-codex-pet` 合并到 `master` 的草稿 Pull Request。
5. PR 描述说明功能、用户价值、接口文档和验证结果。

这种发布方式保留完整提交历史，也让用户能在 GitHub 上审阅最终合并内容。
